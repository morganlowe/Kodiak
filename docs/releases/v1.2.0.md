# Kodiak v1.2.0 — Iterative Conversational Workflow, Plan Approval Gate & BFS Project Discovery

## Executive Summary

Kodiak `v1.2.0` replaces the single-shot pipeline with a full iterative, conversational multi-round workflow while preserving Charter Section 1 guarantees (zero raw file contents leave the machine) and Kodiak's Grant Matrix / Hard Deny-List security model. Operators can review and filter interpreted plans before execution via the Plan Approval Gate, iterate cleanly across rounds in a unified chronological thread (`You` -> `Kodiak`), recover or retry individual stages and steps, rely on breadth-first project discovery so large subdirectories never obscure root entrypoints, and see unambiguous on-disk approval status before approving writes.

---

## Key Highlights & Categorized Changes

### Added
- **Iterative Multi-Round Pipeline**: Added `TaskRoundSnapshot` round archival, `rerun_task_from_stage`, `continue_task_round`, `retry_task_step`, `resume_paused_task`, `cancel_active_iteration`, Stage 2 `pause_on_request` pause/resume flow, two-phase discovery (`discovery_pass_enabled`), and opt-in bounded automatic repair (`auto_repair_enabled`, `max_auto_repair_rounds`).
- **Plan Approval Gate (`pause_after_plan`, default `true`)**: Pauses after Stage 1 Interpret with per-step selection checkboxes, **Approve & Execute Plan**, **Revise Plan** feedback input, and **Discard Plan** actions (`approve_plan_and_execute`, `revise_pending_plan`, `discard_pending_plan`).
- **Unified Conversational Thread & Docked Progress Bar**: Renders chronological `You` -> `Kodiak` turns with a bottom follow-up composer (`Ctrl+Enter`), Stage 3 synthesized `Kodiak Response` cards (`VerificationResult.response`), collapsible archived rounds, collapsible Live Event Ticker, inline Workbench controls, and a permanently docked 4-segment `Interpret | Execute | Verify | Done` progress bar below the Health Strip.
- **Pending Disk-Write Warning Banner**: Displays an explicit **Not yet written to disk** banner on active rounds whenever file/command Action Cards remain `pending_approval`.
- **Follow-Up Objective Promotion & Local Context Seeding**: Added `build_effective_round_prompt` to promote active follow-up requests above the Round 1 prompt and `build_local_prior_round_context` to pass archived step summaries, shell outputs, and prior synthesized answers into local Stage 2 (`draft_code`) execution.
- **Breadth-First File Discovery & Tool Normalization**: Updated `list_project_relative_files` to breadth-first traversal (root files first, 8-file per-subdirectory cap, 80-entry cap) and added `normalize_plan_steps` to map common document/file aliases onto `draft_code`.
- **Expanded Test Coverage**: Added 15 new Rust unit tests covering iterative rounds, Charter §1 isolation, Plan Approval Gate helpers, pause/resume on `REQUEST`, follow-up prompt promotion, tool normalization, and BFS file discovery (85 passing tests total).

### Changed
- Added `CRITICAL APPROVAL-STATUS RULE` in `VERIFY_SYSTEM_PROMPT` so Stage 3 explicitly distinguishes staged `pending_approval` / `dry_run` cards from files already written to disk.
- Updated `INTERPRET_SYSTEM_PROMPT` Rules 5, 10, and 11 for document creation (`draft_code`), follow-up round priority, and representative core-file inspection on project summary tasks.
- Synchronized package versions, documentation, and configuration references (`package.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`, `src-tauri/tauri.conf.json`, `src/main.ts`, `README.md`, `CHANGELOG.md`, `config.example.toml`, `docs/DECISIONS.md`) to `v1.2.0`.

### Fixed
- Fixed cascade error logging (`classify_cascade_attempt_code`) so plan validation errors record `invalid_plan` rather than `429`.
- Fixed `TaskPlan` deserialization aliases (`files_included` / `files` / `target_files`), missing `step.id` normalization, explicit rejection of unsupported `route_tool` names in `validate_plan`, read-only `.` targets for search/diff steps, and UTF-8 character-safe truncation via `truncate_chars`.

## Configuration & Upgrade Notes

All new v1.2.0 `AppConfig` fields use backward-compatible defaults in `~/.config/kodiak/config.toml`:
- `pause_after_plan = true`
- `pause_on_request = true`
- `discovery_pass_enabled = true`
- `auto_repair_enabled = false`
- `max_auto_repair_rounds = 2`

Existing configurations upgrade seamlessly with no manual edits required.
